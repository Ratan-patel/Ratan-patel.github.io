Curriculum

The focus is responsible evaluation: identify a failure mode, demonstrate it with synthetic data, measure risk and propose a control.

WEEK 01 // SYSTEMS

AI threat modeling

Map the model, data, tools, users and trust boundaries before testing.

  • Model and application attack surface
  • Data flows, tenants and secrets
  • Threat actors and misuse cases
  • Lab: create an AI system diagram
WEEK 01 // INPUTS

Prompt injection evaluation

Test instruction boundaries using harmless synthetic scenarios.

  • Direct and indirect instruction conflicts
  • Context separation and trusted data
  • Attack success criteria and limits
  • Lab: build a safe evaluation set
WEEK 02 // DATA

Data leakage and privacy

Measure whether an AI workflow exposes information it should not reveal.

  • Secrets, PII and tenant isolation
  • Logging and retention questions
  • Synthetic canary data design
  • Lab: trace a controlled data-flow failure
WEEK 02 // TOOLS

Tool and agent abuse

Review what an agent can call and what it can change.

  • Tool permissions and input validation
  • Human approval and action boundaries
  • Sandboxing and rollback controls
  • Lab: evaluate a mock tool chain
WEEK 03 // ACCESS

Identity and multi-tenant isolation

Test whether users, sessions and workspaces remain separate.

  • Authorization at model and tool layers
  • Session memory and retrieval boundaries
  • Cross-tenant test design
  • Lab: write an isolation test plan
WEEK 03 // QUALITY

Evaluation and guardrails

Build a small repeatable test suite instead of one-off prompting.

  • Metrics, severity and reproducibility
  • Refusal quality and false positives
  • Regression tests for controls
  • Lab: create a red-team scorecard
WEEK 04 // DEPLOYMENT

Secure AI operations

Connect application controls to monitoring and incident response.

  • Telemetry and review queues
  • Model, prompt and tool change control
  • Abuse handling and rollback
  • Lab: draft an AI incident playbook
WEEK 04 // CAPSTONE

AI risk assessment report

Present a prioritized risk register to technical and business owners.

  • Evidence from synthetic test cases
  • Risk, impact and control mapping
  • Remediation roadmap
  • Final review and certificate

Evaluation workflow

01 // Model

Document the AI system, data sources, tools, identities and trust boundaries.

02 // Test

Run approved synthetic cases with explicit success and stop criteria.

03 // Measure

Record reproducibility, impact, affected boundary and control behavior.

04 // Fix

Propose guardrails, access controls, monitoring and regression tests.
