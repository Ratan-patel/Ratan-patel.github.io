Start with the risk that most often becomes expensive later: unclear authorization, weak access control, poor evidence and untested AI boundaries.

01 // API SECURITY

Before a VAPT: make your API testable

Prepare a written scope, test accounts, route inventory, environment boundary and a named incident contact. Validate authentication separately from authorization; a valid login does not prove that every object or action is correctly protected.

02 // ACCESS CONTROL

BOLA/IDOR is a business-risk problem

Broken object-level authorization appears when an application accepts a record identifier without checking whether the authenticated subject is allowed to access that record. Test only in an approved lab or staging environment, preserve minimal evidence and report the business impact without extracting real customer data.

Server-side checksLeast privilegeSafe evidence

Reference: OWASP Broken Access Control.

03 // AI SECURITY

Prompt injection is an application boundary issue

Do not treat a model instruction as a security boundary. Separate untrusted content from system policy, restrict tools by least privilege, validate outputs and log high-risk actions. Never paste production secrets or personal data into an unapproved assistant.

Tool boundariesData handlingHuman review

Reference: OWASP Top 10 for LLM Applications.

Need advice for a real environment?

Share the business objective, approximate asset count and authorization status. Do not send passwords, API keys, OTPs, customer data or exploit payloads in the first message.
