    What changed in ATT&CK v19

    If your coverage map or detection backlog was last touched before April 2026, it is referencing a tactic that no longer exists. This is the accurate short version.

    DEFENSE EVASION IS GONE

    TA0005 was retired and split into two tactics: Stealth, which keeps the TA0005 ID, and Defense Impairment (TA0112). Hiding inside legitimate behaviour and actively breaking security controls are different problems and now sit in different columns.

    T1562 MERGED AWAY

    T1562 Impair Defenses was retired. It and two of its sub-techniques were merged into a new technique, T1685 Disable or Modify Tools. Any detection rule keyed to T1562 has to be re-pointed.

    TWO NEW DEFENSIVE TACTIC ENTRIES

    T1687 Exploitation for Defense Impairment is new, and T1211 was renamed to Exploitation for Stealth. A new sub-technique T1686.003 covers the Windows host firewall specifically.

    AI IS NOW OFFICIAL TTP

    v19 added T1682 Query Public AI Services and T1683 Generate Content. Adversaries using AI to scale reconnaissance and lure writing are now mapped behaviour, not an analyst's hunch.

    SOCIAL ENGINEERING GOT A PARENT

    A new T1684 Social Engineering parent technique with T1684.001 Impersonation and T1684.002 Email Spoofing re-homes behaviour that used to be scattered across Initial Access.

    DETECTIONS BECAME ANALYTICS

    Back in v18, flat detection lists were replaced by Detection Strategies (DET…) and Analytics (AN…) tied to data components. It is a better model — and it means copy-pasted old mapping tables are quietly wrong.

    SCALE OF THE ENTERPRISE MATRIX

    Post-restructure the Enterprise matrix runs to 15 tactics, 222 techniques and 475 sub-techniques, with roughly 178 tracked threat groups. Nobody covers all of it — which is exactly why you scope to a threat model instead of chasing a percentage.

    PHASE ONE, NOT THE END

    MITRE has flagged that technique descriptions, scope realignments and further deprecations land in later releases. Treat any static spreadsheet as a snapshot, and verify IDs against attack.mitre.org before you ship detection-as-code.

    Adversary emulation in five steps

    Emulation is not "run a C2 and see what happens". It is a hypothesis-driven test of whether defenders can see a specific, documented adversary behaviour.

    1. Choose the adversary that actually threatens you

      Not the most famous one. A regional bank models financially motivated intrusion; a SaaS company models cloud-credential abuse. Pick the group whose goals match your assets, then pull only the tactics you have telemetry for.

    2. Convert the technique list into hypotheses

      Each gap becomes one falsifiable sentence: "If an operator performed credential dumping on this host, our stack would raise an alert within ten minutes and name the host." A hypothesis you cannot state is not a test.

    3. Define the safety envelope before anything runs

      Written authorisation, named asset list, an out-of-band abort channel, a white-cell owner who can halt the run, and a rollback plan for every change. If the abort path is a group chat, the envelope is not real. — generate the authorisation, ROE and abort procedure here.

    4. Run atomically, in order, with the clock visible

      Use one technique per step: note the start time, execute, capture the telemetry you expected to fire, and note what actually fired. Tooling such as Atomic Red Team maps tests to technique IDs and keeps steps small enough to be attributable.

    5. Report per technique, not per tool

      The deliverable is not "we ran Sliver". It is "T1003.001 produced no alert; passive telemetry existed but had no rule; two of three hosts were blind". That sentence costs money to fix, and that is the point.

    How teams usually get this wrong

    01 // COVERAGE THEATRE

    Chasing a percentage

    "We cover 78% of ATT&CK" means nothing without a threat model. Cover the twenty techniques your actual adversary uses, and let the vanity number go.

    02 // LOG ≠ ALERT

    Confusing telemetry with detection

    Sysmon logging process creation is not coverage. A tuned rule that fires, with a triage path behind it, is coverage. Mark anything else as partial.

    03 // STALE MAPPINGS

    Running last year's matrix

    After the v19 split, a map still keyed to Defense Evasion is mis-sorted at the tactic level. Re-check tactic assignment before you argue about technique detail.
